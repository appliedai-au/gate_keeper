# Actual C serving with immutable completed A/B/E history

This v2 completed-history profile lets the ordinary authenticated review app
serve from actual source C while its owner Learning page reads the completed
frozen experiment A, original BASE continuation B, and separately qualified E
observation/remainder execution. It creates no Learning coordinator, admission,
model dispatch, issuer, replacement experiment, or history bank.

The source and its synthetic tests do not establish that the real ten attempts
have completed, that this composed C has passed qualification or merged, or
that actual Base44 sessions have passed acceptance. The prior C v1 qualification
cannot qualify this new source or protocol. All live facts require separate
observed evidence on the final composed source.

## Four explicit source identities

| Identity | Meaning | Evidence preserved |
| --- | --- | --- |
| A | Frozen experiment, policy, corpus, prompts, original public role pins and managed gate | Original bundle, controller, operation archives, gate, and positive/negative bank |
| B | Qualified implementation that completed the original BASE with one retained result plus thirteen new calls | Original B qualification/preparation/owner envelopes, append-only BASE continuation, exact dispatch link, and fourteen-call settlement |
| E | Separately qualified original-fourth observation implementation and explicitly authorized later execution | Exact signed E qualification/preparation/owner envelopes, separate E authority namespace, unchanged original fourth failure, completed host observation cut, and six later genuine proposals |
| C | Actual app image for ordinary reviews and read-only completed Learning history | New exact-C v2 qualification, create-once closure, authenticated owner closure pin, and independent hosted acceptance |

A, B, E and C must be distinct. E is a proof-bound actual implementation input;
there is no placeholder runtime SHA. C never spoofs the Railway source, invokes
the B/E production opener, replaces original qualification objects, or treats
historical execution authorization as permission for C to run Learning. P6's
ordinary review runtime independently requires its configured source to be
actual C.

The frozen policy remains ten genuine proposal attempts, two passes, a minimum
improvement of one, exactly three fresh confirmation pairs for promotion,
positive and negative retained history, and no retry of a negative proposal.
There is no aggregate spending ceiling. Unknown prices remain unknown. Spekky
is waived, and optional issue #42 work is not a prerequisite for this closure.

## The bounded qualified predecessor

For the installed pilot, final execution is the qualified successor E. Its
source proof has one v1 predecessor D, anchored in original B. D is release
provenance; the archived record must not imply that D dispatched the first
eighteen model calls or performed the later recovery. The first eighteen calls
belong to B, the fourth-result consumption adds zero calls under E, and the
remaining six proposal calls belong to E. Public history retains the four
roles A, original B, final E and serving C. The extra qualified predecessor
stays inside the protected source facts.

The private reader reproduces the signer's exact stable projection. V1 facts
remain `gk-learning-proposal-observation-qualified-facts-v1` and require the
single merge `[B, D-qualified]`. V2 facts retain the distinct
`gk-learning-proposal-observation-qualified-facts-v2` schema, exact final merge
`[D, E-qualified]`, and exactly one predecessor merge `[B, D-qualified]`.
`predecessor.descriptor` is the original **nested v1 gate proof**;
`descriptor.sourceProof.previous` retains its outer descriptor and policy.
Neither is reshaped or substituted. A recursive predecessor, self-reference,
wrong anchor, changed tested tree, changed owner, weaker full recipe, reused
qualification run, incomplete checks, missing cleanup or current-head changes
request is refused even when a synthetic test re-signs the changed facts.

The authentic recovery qualification signs the facts digest. During private
export, both original qualification comments are checked against their exact
owner/body pins, cleanup chronology and retained actual-main observation.
The predecessor's qualification must not postdate the successor's. Mutable
GitHub metadata is not inserted into the immutable signed facts. Later C
reads authenticate the original signed fact digest; they do not fetch or
fabricate a response claiming that E or D is still current main.

The previously unintegrated draft `completed-recovery.mjs` helper and its tests
are replaced by the integrated `completed-proposal-observation.mjs` path.
Export, capture, activation and serving now use that same original-output and
cross-journal validator. The replacement race tests append a valid no-op event
after the initial export projection, then require the exact final-read change
rejection for each original and observation journal. They do not truncate a
chain or rely on an earlier unrelated validation failure.

## Exact original-fourth exception

The ordinary archive of attempt four must still contain precisely its original
operation/call claim and `session -> turn -> failure` observations. Its terminal
failure is not deleted, reclassified, overwritten, given a fake `final`, or
followed by a fabricated proposal artifact. The failure remains
`TRUEFORGE_CALL_UNRESOLVED` at `turn-read`, with its original IDs, input, raw
observation facts and bytes.

E's separately signed preparation proves a later read of that same original
owned turn. Its complete original output is invalid under the unchanged
whole-output parser. The original B authority independently settled that one
call; its authentic receipt has `actualCalls: 1` and `actualMicros: null`. The
receipt does not contain owner, request or call fields: those are bound through
the original signed admission, deterministic request, owned intent and provider
evidence. The recovery adds **zero** model calls, while preserving the original
one-call accounting and unknown price.

The host's separate observation sidecar retains the exact original checkpoint,
B and E envelopes, and an append-only completion record. C reuses E's read-only
validator to check the entire original prefix and exact controller/dispatch
consumption suffix, including the mandatory dispatch link, ordinary settlement
observation, original invalid transition, settled transition and completed
cut. That cut must exist before any fifth attempt. Every later read still
requires the unchanged original failure and complete sidecar.

This is the only failure-record exception. It is bounded to original attempt
four, original B settlement and genuine signed E observation. Other provider
failures, reconciliation-only placeholders, merely reserved attempts, invented
output, repeated calls, missing cut records or unknown recovery types remain
ineligible. There is no eleventh replacement proposal.

A ten-attempt closure requires E's authentic owner authorization to contain
`allowRemainingExperiment: true`. Permission sufficient only to consume the
fourth result is insufficient for this profile. E consumption stops at four;
the remaining experiment is a separate invocation under its own explicit
remainder authorization and mandatory local linkage.

## Independent closure evidence

Before capture or serving, the validator requires:

1. Exactly ten uniquely numbered genuine original proposals. Attempts one
   through four are invalid; later outcomes may be invalid, duplicate,
   no-coverage, uncertain, rejected or confirmed only when supported by their
   actual original result and applicable original receipts. Every proposal has
   exactly one owned complete model result and one authentic one-call settlement.
2. The original fourteen-call BASE and its complete B sidecar: retained first
   result, retained original failed second record, thirteen distinct continued
   calls, original schedule/evaluation and fourteen-call settlement. The B
   preparation and authorization remain exact original serialized objects.
3. One-to-one host/controller/dispatch/authority operation, lease, request and
   call sets. Every owned relay is complete, every input/output identity matches
   retained evidence, and no extra or reused model call is counted.
4. All original role signatures, including gate, admissions, settlements,
   evaluations, novelty, activation/renewal and delayed-usage evidence. Final
   counters and a hash-chained final snapshot are not sufficient by themselves.
5. Deterministic invalid and exact-duplicate classification from original text
   and retained history. Genuine negative proposals need not have an evaluation
   complete flag or an evaluation fresh-call counter. Covered uncertain or
   no-coverage outcomes retain their authentic novelty judgment.
6. Actual screening, exactly three required fresh confirmation pairs for every
   positive screen, and a valid chain of confirmed versions and host-consumed
   activation. An authority renewal not consumed by the host holds closure.
7. No pending dispatch, unconsumed operation, provisional attempt, active or
   ambiguous provider intent, incomplete relay, undecided review, writer lock,
   staging link or pending publication. Inventories and heads are rechecked
   after capture and every host serving read.

Lease freshness is evaluated at original admission. The authorized BASE
continuation may finish after that window. Activation freshness is evaluated
at historical host consumption, using the original consumed renewal. C renews
no receipt and does not interpret current clock time as a historical rejection.

## Strict v2 private protocol

The authority capsule is `gk-completed-authority-capsule-v2`. It retains
`originalExecutionSourceCommit` B, `finalExecutionSourceCommit` E, and original B
envelopes under `originalImplementation`. Its `proposalObservation` object has
exactly:

- `qualification`, `preparation`, `authorization`: original serialized signed E
  envelope strings, preserved without normalization or resigning;
- `qualificationFacts`: the exact stable source/receipt/ordered-parent facts
  whose canonical digest is authenticated by E's qualification envelope;
- `provenance`: the separate E journal head, three-event count, final state
  digest/time, original settled authority prefix head/count/state digest, and
  exact original host-checkpoint digest.

The E namespace must consist of exactly qualification initialization,
original-fourth observation, and original owner authorization. C independently
replays all three states and refuses any additional changed field or tail.
It locates the prepared original authority head within the retained original
journal, verifies its complete state digest, and matches that original settled
BASE/four-invalid state to the unchanged first five operations/four attempts
of the final ten-attempt state. It reconstructs the original fourth intent and
matches the retained signed observation to the original evidence artifact.
The actual retained owner evidence must match its signed digest and exact
comment pin, original GitHub owner and explicit remainder permission.

The host closure is `gk-completed-history-closure-v2`; profile activation is
`gk-completed-history-activation-v2`. Both source identities and the complete
E consumption cut are pinned with the original host heads, proof file bytes
and namespace inventory. The capsule, closure, source proof, owner pin and
public response are v2-only. A v1 or hybrid object has no fallback path.

## Read-only custody and protected transfer

The C `authority-export` role reads retained `/data/gk-v4-authority` with
existing-file, read-only `FileJournal` instances for **both** `ledger` and
`proposal-observation`. `AuthorityLedger.read()` receives inert initial state;
no initialize or append method is called. The role does not load issuer key
bytes, create an authority, call a provider, sign, bootstrap or listen.

Secret names/types/ownership/permissions/link counts are checked by metadata
only. Named private intent/evidence artifacts are read because their exact
canonical content digest, byte hash, ownership and original call facts must
be verified. The projection is a strict field allowlist. Raw provider turn or
event archives, arbitrary authority state, prompts, keys, relay prefix and
connection credentials are not exported.

The **one explicit exception** is the original signed E preparation. Its exact
signed body includes the original fourth whole output and private identities;
retaining those protected bytes is necessary to authenticate the signature and
independently reproduce invalidity. It is not an allowance to export other raw
provider material. The public response and owner pin expose only source/digest
identities and the fixed zero-additional-call recovery summary.

The original host `production-config.json` is read solely to validate its full
frozen bundle against authority custody, including retained nonprocedure bank
content. That same file contains credential bytes. Connection fields are
immediately discarded and never used as a client, closure field, log, output
or child environment. The status token remains only in its protected reader.

The external SHA256 pins the complete canonical capsule; no self-referential
digest appears inside it. Capsule provenance distinguishes original authority
and E event times from actual C capture time. The whole final file inventory
is retained. The immutable closure pins `archivedAt`; every successful serving
read generates a fresh `checkedAt` after revalidation.

Transport framing remains the bounded generic `gk-completed-history-transfer-v1`
protocol; its decoded payload must be a strict v2 capsule. Protected output
lines start `GK_COMPLETED_HISTORY_TRANSFER ` and contain one begin record,
numbered 8-KiB chunks and one end record. Boundaries pin capture ID, byte count,
chunk count and SHA256. The decoded limit is 32 MiB. Missing, repeated,
reordered, partial, mixed-capture and noncanonical payloads fail before install.

Use a genuinely available authenticated control-plane staging capability to
place the exact ordered JSON array at:

`/tmp/gk-completed-history-input/authority-transfer.json`

The directory must already be UID 1000/mode 0700, and the regular single-link
file UID 1000/mode 0600 at capture. Native Railway Console upload was separately
verified with a harmless marker before this release packet. For the real
transfer, prepare only the new temporary directory, reopen the Console file
panel and verify its current destination breadcrumb; reopening can reset it
to `/app`. Use the visible Upload control and its file chooser. Upload only the
exact protected ordered transfer array, then verify its byte count and SHA256

The staged JSON array's transport-file hash is distinct from the decoded
canonical capsule SHA256 passed as `GK_COMPLETED_HISTORY_CAPSULE_SHA256`.
Verify both against their observed transfer metadata. Upload support alone

## Read duration and request-local validation

The completed-history bridge has independent bounded deadlines: seven seconds
for the incoming empty JSON body and sixty seconds for the entire protected
upstream fetch plus response body. The UI waits at most seventy-five seconds
for the complete hosted invocation and invalidates late responses. The upstream
deadline is not reset when headers arrive. Authentication, owner pins, response
limits, strict server freshness and fixed failures remain mandatory.

The retained live host inventory observed before this source change contained
239 files and 86,987,316 bytes. A protected status read under the final execution
image took 17,675 ms. That observation rules out the old seven-second upstream
budget, but does not establish the final C duration. Qualify and measure the
actual final C protected route and hosted owner invocation on these retained
bytes; acceptance requires successful validation within their configured
budgets. Preserve the measured duration and resulting source/closure identities.
If the real path still exceeds its bound, keep it unavailable and investigate
the concrete work rather than skipping evidence checks.

Within one `readClosedHostSnapshot` invocation, the first access to each journal
opens a real read-only `FileJournal`, validates its entire hash chain and freezes
every returned object recursively. The existing semantic validators reuse only
that request's immutable snapshots. No mutable validator can alter the retained
cut, and their read-only wrapper has no usable append capability. At the end,
the collector bypasses the wrapper and rereads every actual journal, comparing
the complete snapshot with its original. Full byte inventories and custody
checks still surround the read, including all original archives, sidecars,
proof/config files and extra-name/lock checks. A valid concurrent append is
detected even if it leaves the semantic state unchanged.

The map is local to that one collector call. Every later request, capture check,
activation check and startup creates a new one. There is no cross-request cache,
last-good status, retained unverified snapshot, reduced original-chain check or
alternate serving mode. All signature, source, receipt, chronology and original
failure/linkage checks remain in the integrated path.
