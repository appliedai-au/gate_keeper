# Dashboard React lifecycle qualification

8 November 2026. Addendum to `g8s-dashboard-blueprint.md` and `g8s-dashboard-installation.md`.

## Why the extra qualification exists

The first dashboard candidate's 103 tests exercised the API client and state stores; its React bindings had only syntax checks. Real rendering, effect cleanup and retained callbacks required an additional test surface. This addendum does not mark the hosted Base44 installation or live end-to-end phases complete.

The isolated control run `30628e8d-db8a-4527-a10e-5813f4bff9d5`, exact source `10e8182e757daae44a2270c2a9cbda13e0b39f79`, retained the old production-facing modules and added the React fixture/recipe only. It failed at 2026-11-08T12:06:53.330Z with 126 tests: 108 passed, 18 failed, zero cancellations/skips/TODOs. All existing 103 tests still passed. Thirteen failures were missing non-report-action refusals; five were rendered-route/retained-callback cases. This is evidence that the new assertions detect the original defects, not a historical backend failure.

## Delivered fixes

- `useReport` accepts only overview, reviews, run, settings, repositories and admin reads. Mutations, logout, sign-in/session control and export are not auto-loaded by a render/effect. Unsupported actions throw before effects or transport. Destructive mutations retain their existing explicit confirmation requirements in the client.
- Provider creates a fresh, initially empty model when its router-supplied `initialSlug` or client changes. The previous organization is not rendered under the new route while waiting for a passive effect.
- Each report/configuration hook captures the exact authenticated session snapshot and its mounted lifetime. A stale callback cannot read or save against a newly selected organization, survive an unmount/disable, or regain validity after same-organization reauthentication. Current callbacks continue to work after refresh.
- Settings reads/saves remain revision-bound and preserve edits made during an earlier save. No automatic write retry, unconditional save, or synthetic account authority is introduced.

## Isolated recipe and evidence interpretation

`Dockerfile.dashboard-react-qualify` runs all existing `tests/dashboard-*.test.mjs` tests and the additional `tests/dashboard-react.integration.mjs` using real React DOM and a synthetic JSDOM document. The integration file deliberately does not end in `.test.mjs`: the unchanged inherited backend test glob must not acquire an undeclared React dependency. The new recipe explicitly requires it; there is no optional/skip branch.

The fixture covers server-render rejection of non-report actions, actual mounted route changes, deferred filter responses, old report/editor callbacks, unmount/disable, same-scope refresh, StrictMode effect replay, actual synthetic button events, settings save/readback, server-denial clearing and network-inert preview. All network functions used by the fixture are synthetic; global fetch is replaced with a refusal. JSDOM is not configured to load external resources or run page scripts.

Test-only direct dependencies are pinned in `tests/dashboard-react/package.json` to React/React DOM 19.2.0 and JSDOM 26.1.0. They are installed only in the separate credentialless remote qualification image with lifecycle scripts disabled. No application package manifest, app React version or historical recipe is changed. The fixture's installed transitive dependency lock is generated by npm; the runtime receipt records its SHA256 and the dependency-inventory SHA256. Do not claim a source-committed lockfile or a completely hermetic dependency resolution.

The runtime emits `G8S_REACT_QUALIFICATION` with exact source, deployment, actual runtime versions, complete log byte count/hash, dependency hashes and the terminal Node summary. Qualification uses a finite deadline, never converts a failure to PASS, and includes all earlier dashboard cases. The run's actual terminal result belongs in PR75; this source document does not predeclare it.

## Base44 installation rules retained

Use the existing app and React instance. Do not copy the test-only dependency manifest into Base44 or replace its installed React. Confirm and test the actual hosted version during installation. Keep the dashboard provider below the marketing router, with the stable configured client and the validated router slug. On deliberate organization switching, update router and model consistently; no unknown slug silently selects another organization.

Use report hooks for reads only. User-click handlers invoke supported mutations through the current scoped model/editor and must display actual errors or uncertain results. Do not retain callback functions across a changed organization, account or unmounted component; stale report/editor functions are now blocked defensively.

Real React/JSDOM success is not acceptance of Base44's router/styles, native browser cookies, CORS, GitHub OAuth, account permissions, publication, mobile layout or keyboard behavior. D2 still requires fresh hosted source preimages, builder-only wiring/readback and the actual app build. D3 remains the controller's backend release and #74 transition. D4 requires real authorized end-to-end evidence; D5 is Owen's publication. The recorded Browser originating-context failure is unchanged by this test work.
