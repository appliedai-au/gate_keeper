# Gate Keeper closeout — 8 November 2026

**State locked in.** Gate Keeper v13.1 ties the unchanged OpenAI Codex review rubric on review quality on a fresh sealed holdout, at under half Codex's cost, and beats Qodo PR-Agent. The decision rule for the Stranger Builds entry was: keep and productise the specialist verification and learning layer if it wins on real review outcomes. It is kept. The product is now branded **G8S Gatekeeper** (domain `g8s.app`).

This page records what was measured, what was fixed, what was not changed, and what is still open. Nothing here is a claim beyond the evidence in this repository and the private rows named below.

## 1. Headline result (`gk-holdout-20261107-v13`, burned)

39 sealed tasks (27 planted bugs, 12 clean), three trials, same model and settings for all reviewers (`truefoundry/deepseek-v4-flash-0731`, temperature 0.2, max 8,000 output tokens, no tools). Full report: [`proof/submissions/gk-holdout-20261107-v13/report.md`](../proof/submissions/gk-holdout-20261107-v13/report.md).

| Reviewer | Caught | Catch rate | False alarms | Net | Unparsed | Avg time | Avg cost / review (est.) |
|---|---|---|---|---|---|---|---|
| **Gate Keeper v13.1** | 76/81 | 94% | **13** | **63** | 0 | 5.8 s | $0.00035 |
| Codex rubric (unchanged) | 75/81 | 93% | 15 | 60 | 2 | 13.6 s | $0.00078 |
| Qodo PR-Agent (unchanged, cap 20) | 78/81 | 96% | 25 | 53 | 0 | 4.7 s | $0.00026 |

Paired sign-flip test on per-review net: Gate Keeper vs Codex +3, p = 0.27 (a tie on quality); vs Qodo +10, p = 0.02. Gate Keeper is ahead of Codex on cost, speed and false alarms. Qodo is cheaper and faster per review than Gate Keeper. Costs are estimates from turn metrics, not reconciled with gateway receipts.

Previous holdout (`gk-holdout-20261107-a`, 42 tasks, burned): v12 lost to Codex, net 33 vs 56. v13.1 re-run on those tasks as a development check scored 56, level with Codex.

## 2. What v13 is

`proof/three-agent/gate-keeper-v13.md` (core) and `gate-keeper-v13.1.md` (core plus two learned rules).

- **From the Codex rubric (Apache-2.0, attributed in the prompt):** the flagging test (introduced by the change, discrete, the author would fix it, provably affected, no unstated assumptions), "list every qualifying finding", per-finding confidence with a 0.5 floor, short line ranges.
- **Kept from Gate Keeper:** six hunt passes (boundaries, untrusted input, identity and access, state and concurrency, failure paths, semantics), stated-context rules, "check what the language really does before dismissing", the same-line merge step, and the learning loop.
- **Dropped:** v12's ok/BROKEN checklist and the `quote` output field (broke JSON on code containing double quotes).
- **Learning loop:** TrueForge improve step on training tranches only (t4–t5 fit, t6 check), gate = net +3 with neither split worse. It kept two rules (training net 144 → 151), frozen before the holdout was opened.

## 3. Model sweep and model-specific rules

Seven cheaper models were run through the TrueFoundry gateway on the 81-task combined burned set (dv5 dev set, h8 holdout tasks, hv4), with four arms: Codex, Qodo, Gate Keeper v13 (A) and v13.1 (B). The sweep was stopped once it had answered the question. Only the DeepSeek rows were kept locally; the per-model summaries for the other six were read in-session and are not reproducible from this repository.

- Gate Keeper was best or tied with Codex on 6 of 7 models; Codex was clearly better only on gpt-oss-120b.
- The two learned rules helped on 3 models and hurt on 4. **Lessons are model-specific, not model-agnostic.** Rules now live in per-model overlays under `proof/three-agent/rules/` (first overlay: `deepseek-v4-flash-0731.md`). A rule is promoted to the core prompt only after passing the gate on two model families.

DeepSeek v4 flash, 81 tasks (54 with a planted bug, 27 clean), about 240 reviews per arm (indicative; tasks overlap earlier study and holdout work). The "Caught" denominators differ by arm (157–160 rather than 162) because a few reviews per arm did not complete and were dropped from both numerator and denominator:

| Arm | Caught | False alarms | Net | Clean reviews flagged (of 81 = 27 tasks × 3 trials) | $/review | s/review |
|---|---|---|---|---|---|---|
| Codex | 153/157 (97%) | 47 | 106 | 29/81 | 0.00092 | 13.7 |
| Gate Keeper v13 (A) | 150/160 (94%) | 43 | 107 | 31/81 | 0.00051 | 8.9 |
| Gate Keeper v13.1 (B) | 144/159 (91%) | 36 | 108 | 22/81 | 0.00041 | 7.9 |
| Qodo | 160/160 (100%) | 81 | 79 | 41/81 | 0.00028 | 5.0 |

### A/B correlation check (DeepSeek rows)

Splitting the same rows by task attributes:

- **B's whole gain is on clean tasks and it costs catches on bug tasks.** Bug tasks (54): A 47.3, B 45.0 (−2.3). Clean tasks (27): A −11.0, B −8.0 (+3.0). The lost catches sit in the security and resource-leak categories.
- **The gain is confined to the dev set.** dv5 (32 tasks): B − A = +1.0, false alarms 7.0 → 4.3. h8 (39 sealed tasks): −0.3. hv4 (10): 0.0. On tasks the pipeline had never seen, the rules are neutral to slightly worse.
- **No language or content-tag signal** large enough to be real for the rules. The only attribute effect worth noting is Codex vs Gate Keeper: Codex stronger on Python (+2 on 31 tasks), weaker on JavaScript (−3 on 17 tasks).

Conclusion: there is no "version between A and B" worth tuning from these two rules; their benefit does not generalise.

### Candidates for a v13.2 (not run; needs new tasks, not dv5 or h8)

1. **Confidence floor as a harness setting (Gate Keeper arms only).** v13 emits per-finding confidence; dropping findings below a threshold before scoring targets the clean-code false alarms, which are the biggest remaining drag for every reviewer (Gate Keeper −11 on 27 clean tasks). Needs a run that logs per-finding confidence. Codex and Qodo don't emit confidence, so it cannot apply to them and any report must say so.
2. **Per-language overlay**, keyed like the per-model one, if the Python/JavaScript split reproduces on a second model.
3. **"No finding is the expected answer" calibration line.** Cheap; expected effect a point or two.

Recommendation: ship v13 core plus per-model overlays as is. Run candidate 1 on DeepSeek (about $0.12) after the Stranger Builds deadline.
